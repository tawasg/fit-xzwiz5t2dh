# フィットネス利用管理

フィットネスクラブの「月ごとの利用可能回数」と「実際に利用した回数」を管理する個人用の Web アプリです。
契約上の基準曜日（例：火曜・日曜）からその月の利用可能回数を自動計算し、未使用分を翌月へ繰り越します。

---

## 1. 採用した構成と、無料で運用できる理由

| 項目 | 採用したもの | 無料である理由 |
| --- | --- | --- |
| アプリ本体 | HTML + CSS + JavaScript の 1 ファイル（`index.html`） | ビルド不要。フレームワークもライブラリも使っていないため、有料サービスへの依存がありません |
| データ保存 | ブラウザの `localStorage` | 端末内に保存されるため、データベースサーバーが不要です |
| サーバー処理 | なし（すべてブラウザ内で計算） | アプリケーションサーバーが不要なので、実行にかかる費用が発生しません |
| ホスティング | GitHub Pages（静的ファイル配信） | 公開リポジトリなら無料。クレジットカード登録も不要です |
| オフライン対応・アプリ化 | PWA（`manifest.json` + `sw.js`） | ブラウザの標準機能のみ。App Store も Apple Developer Program も不要です |
| 外部 API | 使用していない | 継続的な API 利用料が発生しません |

### データの扱い

- 利用実績・設定は、すべて**その端末の Safari の中だけ**に保存されます。
- アプリは外部へデータを送信する処理を一切持っていません（通信するのは、初回にアプリ本体のファイルを読み込むときだけです）。
- そのため、利用データが第三者へ送られる経路がありません。

### 自分だけが使えるようにする仕組み（3 層）

このアプリは次の 3 つを重ねることで、実質的に自分専用にしています。

**第 1 層：データが端末から出ない**

利用実績はすべて端末内の `localStorage` に保存され、外部へ送信されません。
そのため、**第三者が URL を開いても表示されるのは「空のアプリ」だけ**で、あなたの記録は一切見えません。
守るべきデータがそもそもサーバー上に存在しない、という設計です。

**第 2 層：推測されない URL**

GitHub のリポジトリ名をランダムな英数字にすることで、URL 自体が実質的なパスワードになります。
`index.html` には `noindex, nofollow, noarchive` を指定済みなので、Google などの検索結果にも載りません。

**第 3 層：パスコードロック（任意・推奨）**

パスコードを設定すると、URL を知っている人でも入力なしでは中を開けません。

1. アプリの「設定とバックアップ」→「**パスコードロック**」を開きます
2. 好きなパスコード（4 文字以上）を入力して「**生成**」を押します
3. `window.APP_LOCK = "…";` という 1 行が表示され、クリップボードにコピーされます
4. `index.html` の先頭付近にある次の行を、その 1 行と入れ替えます

   ```js
   window.APP_LOCK = null;
   ```

5. GitHub に `index.html` を再アップロードします

以降、URL を開くとパスコード入力画面が出ます。正しく入力した端末は次回から入力を省略し、
「この端末を再ロックする」を押すと再び入力を求めます。

パスコードは PBKDF2（SHA-256・25 万回）で変換した文字列だけをファイルに書き込むため、
**パスコードそのものはどこにも保存も送信もされません**。変換はブラウザ内で完結します。

> **正直な限界：** `index.html` は誰でも読める公開ファイルなので、変換後の文字列も見えます。
> 専門知識のある人が本気で総当たりすれば、短いパスコードは破られる可能性があります。
> ただし破った先にあるのは「空のアプリ」だけです。実害を伴う情報は保存されていません。
> より厳密な認証が必要な場合は、後述の「補足 D」を参照してください。

複雑なログイン機能（ID・パスワード管理、サーバー側認証）は、この用途では不要です。

## 2. 「localhost」で表示されている理由（重要）

開発中に表示していた `http://localhost:8765/` は、**動作確認のためにこのパソコンの中だけで一時的に起動したサーバー**です。

- `localhost` は「このパソコン自身」を指す特別なアドレスです
- そのため、**パソコンを閉じるとアクセスできなくなります**
- **iPhone からもアクセスできません**（同じパソコンの中でしか見えないため）

iPhone で普段使いするには、次章の手順で **GitHub Pages に公開する**必要があります。
公開すると `https://ユーザー名.github.io/リポジトリ名/` という URL になり、

- パソコンの電源が入っていなくても使えます
- iPhone の Safari から開けます
- ホーム画面に追加してアプリのように使えます
- 一度ホーム画面に追加すれば、機内モードなど通信がない状態でも起動できます（Service Worker のキャッシュ）

**まとめ：localhost は開発中の一時的なもの。実際に使うには第 5 章の公開手順を実行してください。**

## 4. 使い方

### 最初に一度だけ行う設定

1. アプリを開き、いちばん下の「**設定とバックアップ**」をタップして開きます。
2. 「**基準曜日**」で、契約上の曜日をすべて選びます（初期設定は **日・火**）。
3. 必要に応じて「**繰り越し**」の設定を変更します。

設定は自動保存されるため、毎月やり直す必要はありません。

### 毎回の操作

- ジムに行った日に、画面下の「**今日行った**」ボタンを押すだけです。
- 過去の日付は、カレンダーを前月に切り替えて、その日をタップすれば記録できます。
- 同じ日付は二重に登録できないようになっています。

**取り消し方（2通り・確認ダイアログなし）**

| 方法 | 操作 |
| --- | --- |
| 押した直後 | 画面下に出るメッセージの「**元に戻す**」を押す（約5秒間表示） |
| カレンダーから | 紫の丸になっている日付を**もう一度タップ**する |

どちらも確認ダイアログは出ません。すぐに反映され、そのあと出るメッセージの「**元に戻す**」でも戻せます。
利用した日の一覧や、月ごとの記録の確認は、カレンダーを前月・翌月に切り替えて見る形になっています。

### 画面に表示される内容

最初の画面を開くだけで、次のすべてが確認できます。

| 表示 | 意味 |
| --- | --- |
| 大きな数字「のこり」 | 残り回数（超過した月は「オーバー」と赤字に切り替わります） |
| そのすぐ下の行（例 `2 / 11 回利用済み`） | 利用済み ／ 利用可能回数 |
| ピンクのタグ（例 `日曜日 5回`） | 基準曜日がその月に何回あるか |

さらに「**内訳を見る**」を開くと、基本回数・前月からの繰り越し・翌月への繰り越し見込みまで確認できます。

カレンダーの色分けは次のとおりです。

- **薄いピンクの四角**：基準曜日
- **紫の丸**：実際に利用した日
- 両方に該当する日は、ピンクの四角の上に紫の丸が重なって表示されます
- **黒い枠**：今日
- **斜線のハッチ**：月曜日（定休日）
- 未来の日付は薄く表示され、記録できません

### 定休日（月曜日）

道場は月曜が定休日のため、次のように扱われます。

- カレンダーの月曜は斜線のハッチで表示されます
- 月曜をタップしても記録されず、「月曜日は定休日です」と表示されます
- 今日が月曜のとき、下部のボタンは「本日は定休日」になり押せません
- 「基準曜日」の設定でも月曜は選べません（取り消し線付きで無効表示）

> 過去に月曜として記録済みのデータがある場合、それは消えずに残ります（取り消しも可能です）。新しく月曜を記録することだけができません。

### レベルとレベルアップ試験

「レベル」カードに、現在のレベルと昇級試験までの進捗が表示されます。

| 表示 | 意味 |
| --- | --- |
| Level バッジ | 現在のレベル（時間割と同じ色） |
| `9 / 30回` | 現レベルで記録した回数 ／ 昇級に必要な 30 回 |
| プログレスバー | 進捗。条件を満たすと緑に変わります |

- **レベルアップ試験（ベルトテスト）を受けるには、現在のレベルで 30 回受講する必要があります**（30 回は固定値です）
- 30 回に達すると「受験資格あり」と表示され、ベルトテストの開催日時（**日曜 18:00**）が案内されます
- 試験に合格したら「**試験に合格した → Level 2 へ**」ボタンを押します。レベルが上がり、回数が 0 からカウントし直されます
- 誤って押した場合は、下に出るメッセージの「**元に戻す**」で戻せます

### 今のレベルを登録する

「設定とバックアップ」を開くと、いちばん上に「**今のレベルを登録**」があります。

- **1〜5 のボタンをタップするだけ**で現在のレベルが登録されます
- 選択中のレベルは、時間割と同じ色＋紫の枠で示されます
- タイムテーブルの表示も、選んだレベルのクラスに自動で切り替わります
- 間違えた場合は、下に出るメッセージの「**元に戻す**」で戻せます
- 「現レベルの開始日」を設定すると、その日以降の記録だけが 30 回のカウント対象になります

### タイムテーブル

**画面のいちばん上**に表示されます。内容は次のとおりです。

- 右上に現在のレベルのバッジ
- **次のクラス**（今日・明日・曜日で表示。今日が月曜なら「本日は定休日 ― 次のクラス」に変わります）
- **自分のレベルが出られるクラスだけ**を曜日ごとに一覧（時刻はタップしやすいピル表示、今日の行は紫で強調）

レベルが上がると、表示されるクラスは自動で切り替わります。
「**全レベルの時間割を見る**」を開くと、道場の全時間割が表示されます。

| 色 | 内容 |
| --- | --- |
| 白 | Level 1 |
| 黄 | Level 2 |
| 橙 | Level 3 |
| 緑 | Level 4 |
| 青緑 | Level 5 |
| 水色 | イベント（土 18:00〜） |
| 紫 | ベルトテスト（日 18:00〜） |
| 斜線 | 定休日（月） |

マスの数字は対象レベルを表し（`2&3` は Level 2 と 3 の合同クラス）、
**紫の枠**が付いているマスが自分のレベルのクラスです。

### 繰り越しの仕様

- 未使用回数は、設定した有効期間のあいだ翌月以降へ繰り越されます（初期設定は「翌月まで」）。
- 期限が近い回数から先に消費されるため、繰り越し分が無駄になりにくくなっています。
- 利用済みが利用可能回数を超えた月は、**翌月への繰り越しは 0 回**です。超過分を翌月から差し引くことはしません。
- 過去の月の実績を修正すると、その月以降の繰り越しが自動的に再計算されます。
- 設定で変更できるもの：繰り越しの有効・無効／有効期間（何か月先まで）／繰り越せる最大回数（空欄で上限なし）

### バックアップ

「設定とバックアップ」の中に、次のボタンがあります。

- **JSON書き出し**：設定と全記録をまとめたバックアップファイルを保存します（復元に使えます）
- **CSV書き出し**：利用した日付の一覧を表計算ソフト向けに保存します
- **JSON読み込み**：書き出した JSON ファイルを選んで、データを復元します
- **表示してコピー**：ファイル保存がうまくいかない場合に、内容をコピーしてメモアプリなどに貼り付けられます

> Safari のデータを削除したり、端末を初期化するとデータは消えます。月に一度など、定期的に書き出しておくことをおすすめします。

## 5. GitHub Pages で公開する手順

パソコンのブラウザだけで完結します。Git コマンドの知識は不要です。

### 手順 1：GitHub のアカウントを作る

1. https://github.com/signup を開きます。
2. メールアドレス・パスワード・ユーザー名を入力して登録します。
3. 届いたメールのコードを入力して、メールアドレスを確認します。
4. プラン選択が表示されたら「**Free**」を選びます。クレジットカードの登録は不要です。

### 手順 2：リポジトリを作る（名前はランダムな文字列にする）

1. GitHub にログインし、画面右上の「**＋**」→「**New repository**」をクリックします。
2. 「**Repository name**」に、推測されにくい名前を入力します。
   - 例：`fit-log-7q3xk9m2` のように、意味のない英数字を 8 文字以上つなげます
   - この文字列が公開 URL に入るため、`fitness` のようなわかりやすい名前は避けてください
3. 公開設定は「**Public**」を選びます。
   - GitHub Pages を無料で使うには Public が必要です
   - 公開されるのはアプリのファイルだけで、あなたの利用実績は含まれません
4. 「**Create repository**」をクリックします。

### 手順 3：ファイルをアップロードする

1. 作成されたリポジトリの画面で「**uploading an existing file**」というリンクをクリックします。
   - 見つからない場合は「**Add file**」→「**Upload files**」でも同じです
2. パソコンのエクスプローラーで、このフォルダの中身を選びます。
   - `index.html`、`manifest.json`、`sw.js`、`icons` フォルダ をまとめてドラッグ＆ドロップします
   - `README.md` と `.claude` フォルダは、アップロードしなくても動きます
3. 画面下の「**Commit changes**」をクリックします。

> **重要：** `icons` フォルダは、フォルダごとドラッグしてください。中身のファイルだけを入れると、アイコンのパスが合わなくなります。

### 手順 4：GitHub Pages を有効にする

1. リポジトリ上部の「**Settings**」をクリックします。
2. 左のメニューから「**Pages**」を選びます。
3. 「Build and deployment」の「**Source**」で「**Deploy from a branch**」を選びます。
4. 「**Branch**」で「**main**」、フォルダは「**/ (root)**」を選び、「**Save**」をクリックします。
5. 1〜2 分待ってページを再読み込みすると、上部に URL が表示されます。

```
https://<あなたのユーザー名>.github.io/<リポジトリ名>/
```

例：`https://taro123.github.io/fit-log-7q3xk9m2/`

この URL を開いてアプリが表示されれば公開完了です。**URL は他人に教えないでください。**

### 手順 5：iPhone のホーム画面に追加する

1. iPhone の **Safari**（Chrome ではなく Safari）で、手順 4 の URL を開きます。
2. 画面下中央の「**共有**」ボタン（□に↑のアイコン）をタップします。
3. メニューを下にスクロールし、「**ホーム画面に追加**」をタップします。
4. 名前を確認して（「フィットネス」と入ります）、右上の「**追加**」をタップします。
5. ホーム画面のアイコンから起動すると、Safari のアドレスバーが出ない全画面表示になります。

> ホーム画面から起動したアプリと、Safari のタブで開いたアプリは、同じデータを共有します。

### ファイルを更新したときの注意

`index.html` を修正して再アップロードするときは、`sw.js` の 1 行目付近にある

```js
const CACHE = "fitness-v6";
```

の `v6` を `v7`、`v8` … と増やしてください。
これを変えないと、古いファイルがキャッシュから読み込まれて更新が反映されないことがあります。

## 7. 補足

### 補足 A：パソコンでローカルに動作確認する

`index.html` をダブルクリックして開くだけでも、ほとんどの機能が動きます。
オフライン動作（Service Worker）まで確認したい場合は、簡易サーバー経由で開いてください。

```bash
python -m http.server 8765
```

実行後、ブラウザで `http://localhost:8765/` を開きます。

> Windows では、`python -m http.server` が `.js` ファイルを `text/plain` として配信することがあり、
> その場合ローカルでは Service Worker の登録に失敗します（アプリ本体の動作には影響しません）。
> GitHub Pages では正しい形式で配信されるため、公開後は正常に登録されます。

### 補足 B：公開せずに使う

インターネットに公開したくない場合は、次の方法でも使えます。

- ファイルを iCloud Drive などに置き、iPhone の「ファイル」アプリから `index.html` を開く
- ただしこの方法では、Safari の「ホーム画面に追加」でアプリのように使うことはできません

ホーム画面に追加して普段使いするなら、第 5 章の「推測されにくい URL で公開する」方法が最も手軽です。

### 補足 C：iPhone のホーム画面アイコンについて

`icons/` に用途別のアイコンを用意済みです。追加作業は不要です。

| ファイル | 用途 |
| --- | --- |
| `icon-32.png` / `icon-64.png` | ブラウザのタブに出る小さなアイコン（favicon） |
| `icon-180.png` | iPhone の「ホーム画面に追加」で使われるアイコン |
| `icon-192.png` / `icon-512.png` | PWA として登録されたときのアイコン |
| `icon-maskable-512.png` | Android の丸型／角丸に切り抜かれる形式 |

iPhone のショートカット（ホーム画面に追加）では `icon-180.png` が自動で使われるため、
アイコンを自分で選び直す必要はありません。

> アイコンを差し替えたい場合は、`icons/` の中の同じファイル名の PNG を置き換えて、
> `sw.js` の `CACHE` の番号を 1 つ増やしてから再アップロードしてください。

### 補足 D：もっと厳密な認証が必要な場合

「変換後の文字列すら見せたくない」「サーバー側で認証したい」という場合は、
GitHub Pages ではなく **Cloudflare Pages + Cloudflare Access** を使う構成があります。

- 同じ静的ファイルをそのまま置けます（アプリの変更は不要）
- Cloudflare Access の無料枠で、指定したメールアドレスにワンタイムコードを送る認証がかけられます
- 認証を通っていないアクセスは、ファイルが配信される前にブロックされます

ただし設定項目が多く、初回のセットアップは GitHub Pages よりかなり複雑です。
本アプリは端末内にしかデータを持たないため、通常はここまでする必要はありません。

### 補足 E：機種変更したときのデータ移行

1. 古い端末でアプリを開き、「設定とバックアップ」→「**JSON書き出し**」でファイルを保存します。
2. そのファイルを新しい端末に移します（AirDrop、メール添付、iCloud Drive など）。
3. 新しい端末でアプリを開き、「**JSON読み込み**」からそのファイルを選びます。

## 8. 動作確認済みの項目

- iPhone Safari を想定した幅（375px）で、横スクロールが発生しないこと
- ホーム画面に追加するための設定（`manifest.json`、apple-touch-icon、standalone 表示）が揃っていること
- 基準曜日の月ごとの回数が正しく数えられること
  （例：2026年8月＝日曜 5 回 ＋ 火曜 4 回 ＝ 9 回、2026年7月＝日曜 4 回 ＋ 火曜 4 回 ＝ 8 回）
- 繰り越しが正しく加算されること（2026年7月に 8 回中 6 回利用 → 8月の利用可能回数が 9 ＋ 2 ＝ 11 回）
- 基準曜日以外の日でも、同じ週に複数回でも記録できること
- 同じ日付を二重に登録できないこと（「既に記録済みです」と表示される）
- 未来の日付を誤って登録できないこと
- 利用済みが利用可能回数を超えた月に、超過表示が出て、翌月への繰り越しが 0 回になること
- 過去の月の実績を修正すると、それ以降の月の繰り越しが再計算されること
- 繰り越しの有効・無効／有効期間／上限の設定が計算に反映されること
- ブラウザを閉じても（再読み込み後も）記録と設定が保持されること
- 月をまたいで前月・翌月へ切り替えても、記録が保持され正しく集計されること
- オフライン起動用のファイルが Service Worker にキャッシュされること
- アプリが外部へデータを送信する処理を持たないこと
